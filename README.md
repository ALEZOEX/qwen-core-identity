# QWEN CORE IDENTITY v19.2 (Production API & Robust BIO Edition)

Данный репозиторий содержит мастер-промпт корпоративного уровня (Enterprise System Prompt) для преобразования базовых LLM в автономные когнитивные системы. Архитектура промпта перестраивает работу трансформера, внедряя строгие циклы самопроверки, механизмы управления долговременной памятью (Knowledge Graphs) и защиту от авторегрессионных галлюцинаций.

Версия 19.2 представляет собой долгосрочный релиз (LTS), в котором окончательно решены проблемы нестабильного API-парсинга инструментов и внедрена строгая инженерия безопасности кода (Domain-Specific Red Teaming).

## Ключевые нововведения (от v10.6 к v19.2)

### 1. Надежный формат Entity Resolution (KV-Сериализация Графа Знаний)
Модель больше не галлюцинирует JSON-схемы для работы с профилем памяти (инструмент `bio`). Для избежания падений API бэкенда внедрена плоская Key-Value сериализация параметров: `entity:X|status:unverified|mentions:N`.
Система научилась молчаливо регистрировать новые, неопознанные объекты (Deferred Resolution) в режиме фонового трекинга без создания дискомфорта для пользователя навязчивыми вопросами. 

### 2. Time-Based Garbage Collection & Freshness Validation
- Очистка профиля от «мусорных» данных больше не полагается на примитивный счетчик упоминаний. Введен жесткий лимит жизни неопознанной сущности: если параметр `last_updated` старше 180 дней без подтверждения статуса, система системно очищает память (`bio.delete()`).
- Сверхстрогая кросс-верификация (Hard Facts): Источники высшего приоритета (RFC, официальная документация) не принимаются за истину (Single-source exception), если дата публикации превышает 12 месяцев.

### 3. Active Feedback Loop (Протокол подтверждения допущений)
Для задач среднего и сложного типа модель в обязательном порядке отмечает допущения меткой `[assumption]` и запрашивает прямую обратную связь пользователя в конце вывода. Это предотвращает каскадное развитие логических ошибок в случае неполных технических заданий.

### 4. Динамическое распределение вычислений и MoE
Внедрена строгая маршрутизация ресурсов в зависимости от сложности запроса. Для критических и сложнейших архитектурных (high-load, eBPF, blockchain, optics) задач система генерирует обязательную markdown-матрицу решений (CONFLICT RESOLUTION MATRIX), после чего инициирует дискуссию внутренних экспертов (Теоретик, Параноик, Компилятор) в блоке скрытого мышления до выдачи итогового решения.

### 5. Тотальный запрет на извинения и эмодзи (Autoregressive Lock)
Поскольку модель генерирует токены строго последовательно, извинения за допущенную в коде ошибку внутри финального текста признаны недопустимыми. Система заблокирована (No Self-Review Loop): все тесты на прочность (включая безопасность управления памятью в циклах без malloc/new) проводятся внутри секции Анализа. Политика нулевого использования эмодзи позволяет перенаправить контекстное внимание модели исключительно на факты.
